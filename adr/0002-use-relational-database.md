# ADR-0002: Use relational database (PostgreSQL + H2 profile)

## Контекст и постановка задачи

TypePulse должен сохранять пользователей, результаты тренировок и строить историю/рейтинг (REQ-FUNC-005…007). После раунда 2 добавляются пользовательские тексты (SYS-F-08). Нужно выбрать способ хранения.

Вопрос: **какое хранилище обеспечить целостность связей User–Result–Text и простые агрегации для leaderboard при минимальной стоимости сопровождения?**

Связь: SDD VIEW-003, VIEW-008; SYS-NF-03.

## Драйверы решения

* Реляционные связи и уникальность email/login
* Запросы «последние 50 результатов пользователя» и «топ-20 WPM»
* Локальный запуск без обязательной установки сервера БД (демо)
* Стоимость и сложность (учебный проект)

## Рассмотренные варианты

* PostgreSQL в целевом профиле + H2 in-memory/file для local/demo
* Только документное хранилище (MongoDB)
* Только файлы JSON на диске

## Итог решения

Выбранный вариант: **PostgreSQL (+ H2 Spring profile для local/demo)**, потому что лучше всего закрывает целостность данных и агрегации рейтинга, сохраняя простой локальный профиль для защиты лабы.

### Последствия

* Хорошо, потому что схема и миграции (Flyway/Liquibase) дают воспроизводимость
* Хорошо, потому что индексы по `(user_id, finished_at)` и `(best_wpm)` закрывают SYS-NF-03
* Плохо, потому что нужно следить за совместимостью SQL H2 ↔ PostgreSQL
* Нейтрально, потому что объёмы MVP малы

### Подтверждение

* Два Spring-профиля: `local` (H2), `prod` (PostgreSQL)
* Интеграционный тест: сохранить Result → увидеть в History

## Плюсы и минусы вариантов

### PostgreSQL + H2 profile

* Хорошо, потому что стандартный выбор для Spring Data JPA
* Хорошо, потому что Заказчик получает историю/рейтинг без «сюрпризов» консистентности
* Плохо, потому что два профиля надо тестировать

### MongoDB

* Хорошо, потому что гибкие документы для текстов
* Плохо, потому что рейтинг и связи всё равно потребуют дисциплины схемы
* Плохо, потому что лишняя технология в учебном стеке

### JSON-файлы

* Хорошо, потому что ноль инфраструктуры
* Плохо, потому что гонки при одновременных записях и слабый рейтинг
* Плохо, потому что плохо масштабируется даже до учебной группы

## Дополнительная информация

Админский CRUD каталога текстов (SYS-F-09) отложен; custom texts хранятся в той же таблице `TextSnippet` с `ownerUserId != null`.
